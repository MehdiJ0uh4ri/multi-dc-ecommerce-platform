# Observability (Phase 6)

| Signal | Components | Where |
|---|---|---|
| Metrics | kube-prometheus-stack (Prometheus, Alertmanager, Grafana, kube-state-metrics, node-exporter) | `monitoring` |
| Scrape config | `charts/observability` PodMonitors/ServiceMonitors, plus the charts' own monitors (APISIX, Keycloak, exporters) | `monitoring`, DC namespaces |
| Logs | Fluent Bit DaemonSet → ECK Elasticsearch `es-logs` → Kibana | `logging` |
| Uptime / alerting | Icinga 2 + Icinga DB + Icinga Web 2 (`charts/icinga`), with Alertmanager rules; both send mail to Mailpit in DC2 | `monitoring` |

## What is scraped

| Target | How | Port |
|---|---|---|
| Spring services (both DCs) | ServiceMonitor `spring-services` (label `app.kubernetes.io/part-of=ecommerce`), `/actuator/prometheus` | 9000 |
| Kafka brokers, Connect, MirrorMaker 2 | PodMonitor `strimzi-kafka-resources`, with JMX exporter configs in `charts/datastores/files/` | 9404 |
| Kafka consumer lag | Strimzi Kafka Exporter (`kafkaExporter` in the Kafka CR), same PodMonitor | 9404 |
| PostgreSQL (CloudNativePG) | PodMonitor `cnpg-clusters` | 9187 |
| Cassandra | PodMonitor `cassandra` (management API `/metrics`) | 9000 |
| RabbitMQ | ServiceMonitor `rabbitmq`, from cluster-operator v2.23.0 | 15692 |
| Elasticsearch / MongoDB (DC2) | prometheus-community exporters, deployed next to the stores | 9108 / 9216 |
| APISIX | chart ServiceMonitor (`apisix.prometheus.enabled`) | 9091 |
| Keycloak | chart ServiceMonitor (management `/metrics`) | 9000 |

Prometheus runs in `monitoring`. It reaches the DC pods only through the `allow-monitoring` NetworkPolicy in each DC (`terraform/network-policies.tf`).

Services publish `http.server.requests` histogram buckets (`MANAGEMENT_METRICS_DISTRIBUTION_PERCENTILES_HISTOGRAM_HTTP_SERVER_REQUESTS=true`), so p95 latency can be computed.

## Dashboards (Grafana folder "Platform")

All dashboards live in `monitoring/grafana-dashboards/` and are loaded by the Grafana sidecar from ConfigMaps labelled `grafana_dashboard=1`.

- **`platform-overview.json`** (written for this platform):
  - requests/s, p95 latency and 5xx rate per service
  - APISIX p95 per route
  - Hikari active/pending connections
  - PostgreSQL backends per database
  - Kafka consumer-group lag
  - MirrorMaker 2 replication latency
  - connectors not running
- **Strimzi 1.2.0 upstream, unmodified:** Kafka, KRaft, Kafka Exporter (lag), Kafka Connect, MirrorMaker 2, Operators.
- **CloudNativePG upstream cluster dashboard:** `cnpg-cluster.json`.

## Alerting

- **Prometheus rules** (`charts/observability/templates/prometheus-rules.yaml`):
  - Kafka lag, broker not ready, connector failed
  - PostgreSQL instance down or no ready instance
  - Elasticsearch not green, RabbitMQ backlog
  - service p95, 5xx ratio, service down

  Alertmanager mails `oncall@platform.local` through Mailpit (`mailpit-smtp.dc2-analytics:25`).
- **Icinga** (`monitoring/icinga/platform.conf.tftpl`, rendered from the `enable_*` toggles):
  - **TCP checks** on each data store and Kafka bootstrap in both DCs, plus Kafka Connect.
  - **HTTP checks** on Keycloak OIDC discovery, the APISIX public catalog route, Kafka Connect `/connectors` and RustFS `/health`.
  - Problems and recoveries are mailed through msmtp to Mailpit.

## Access (port-forward)

Passwords are generated by `make secrets` into `ansible/.secrets/<key>`.

| UI | Command | URL | Login |
|---|---|---|---|
| Grafana | `kubectl -n monitoring port-forward svc/kps-grafana 3000:80` | http://localhost:3000 | `admin` / `ansible/.secrets/grafana_admin` |
| Prometheus | `kubectl -n monitoring port-forward svc/kps-prometheus 9090` | http://localhost:9090 | — |
| Alertmanager | `kubectl -n monitoring port-forward svc/kps-alertmanager 9093` | http://localhost:9093 | — |
| Kibana | `kubectl -n logging port-forward svc/kibana-kb-http 5601` | http://localhost:5601 | `elastic` / `kubectl -n logging get secret es-logs-es-elastic-user -o jsonpath='{.data.elastic}' \| base64 -d` |
| Icinga Web 2 | `kubectl -n monitoring port-forward svc/icinga-icingaweb2 8081:80` | http://localhost:8081 | `icingaadmin` / `ansible/.secrets/icingaweb_admin` |
| Mailpit (alert mail) | `kubectl -n dc2-analytics port-forward svc/mailpit-http 8025:80` | http://localhost:8025 | — |
| Chaos Mesh | `kubectl -n chaos-mesh port-forward svc/chaos-dashboard 2333` | http://localhost:2333 | RBAC token (see Chaos Mesh docs) |

Kibana: create a data view on `k8s-*`, then filter `kubernetes.namespace_name : "dc1-core"` or `"dc2-analytics"`.
